# Think Tank Research: Senior Developer Final Report (v2)
**Author:** Marcus (Senior Developer / Architect)
**Project:** AlienSky v2 - Pure Atmospheric Scattering
**Date:** Conclusion of Month 4 Think Tank (Re-evaluation Phase)

## Executive Summary

Following direct feedback from the project lead, the AlienSky v2 architecture has undergone a significant realignment. The primary directives were twofold:
1. **Atomic Scoping:** Isolate the atmospheric scattering logic from volumetric clouds. Clouds will be developed as a separate, independent library in the future.
2. **Maximized Hardware Utilization:** Abandon the "lowest common denominator" approach. Develop two distinct rendering backends to fully leverage WebGPU's compute capabilities while maintaining a WebGL2 fallback.

This report outlines the finalized architecture for a pure, highly optimized, and extensible Atmospheric Scattering library for Babylon.js.

---

## 1. Atomic Library Philosophy

AlienSky v2 is now strictly an atmospheric rendering engine. By removing the volumetric cloud requirements, we have streamlined the codebase and freed up performance budget to perfect the atmospheric math (Hillaire 2020). 

This atomic approach benefits the end-user by allowing them to include only the systems they need. If a game requires a beautiful sky but no clouds, they do not pay the performance or memory overhead of a cloud system. 

To ensure future compatibility with an `AlienClouds` library, AlienSky v2 acts as a "Lighting Data Provider." It exposes its internal Look-Up Tables (LUTs) and calculates Spherical Harmonics (SH) for ambient lighting, which external libraries can consume.

---

## 2. The Dual-Backend Architecture

To provide the best possible performance on modern hardware without sacrificing compatibility, AlienSky v2 utilizes a Facade pattern (`class AlienSky`) that hides two completely separate rendering implementations.

### 2.1 The WebGPU Backend (WGSL)
When `engine.isWebGPU` is true, the library utilizes the `AlienSkyWebGPUBackend`.
- **Compute Shaders:** All LUT generation (Transmittance, Multi-Scattering, Sky-View) is performed using WGSL Compute Shaders dispatched via Babylon's `ComputeShader` API.
- **Direct Storage:** Compute shaders write directly to `texture_storage_2d` and `texture_storage_3d`, bypassing the vertex/rasterization pipeline entirely.
- **Aerial Perspective:** We generate a true 32x32x32 3D LUT for the camera volume, allowing opaque geometry to sample physically accurate volumetric fog.
- **Synchronization:** Relies on WebGPU's implicit memory barriers between compute and render passes, ensuring zero-latency sky updates without pipeline stalls.

### 2.2 The WebGL2 Fallback Backend (GLSL)
When WebGPU is unavailable, the library falls back to `AlienSkyWebGLBackend`.
- **Fragment Shaders:** LUTs are generated by rendering full-screen quads to `RenderTargetTexture` instances using GLSL.
- **2D Atlas Workaround:** Because WebGL2 cannot easily render into 3D textures, the Aerial Perspective volume is unrolled into a 1024x32 2D texture atlas. Materials perform manual trilinear interpolation across slices.
- **Double Buffering:** To prevent pipeline stalls on older OpenGL drivers, dynamic LUTs (Sky-View) are double-buffered, introducing a negligible 1-frame latency to lighting updates.

---

## 3. Extensibility API (The Cloud Hook)

To fulfill the requirement that future libraries can be "atomically added," AlienSky v2 provides a robust public API for data extraction and injection.

### 3.1 Data Extraction (Lighting the Clouds)
Future volumetric systems can query AlienSky for lighting data:
- `getTransmittanceLUT()`: Used to calculate how much direct sunlight reaches a cloud voxel.
- `getSkySphericalHarmonics()`: The Atmosphere library projects the sky's radiance into 9 SH coefficients. External libraries use this for cheap, physically accurate ambient lighting.
- `getCameraVolumeLUT()`: Used to apply atmospheric fog *over* the clouds, grounding them in the scene.

### 3.2 Data Injection (Shadowing the Atmosphere)
External systems can influence the sky rendering:
- `setCloudShadowMap(texture)`: If an external library (or a static texture) provides a shadow mask, the Atmosphere library will incorporate it into the Sky-View and Aerial Perspective raymarching. This allows clouds to cast volumetric god rays through the atmosphere, despite the libraries being completely decoupled.

---

## Conclusion

The pivot to an atomic, dual-backend architecture has resulted in a significantly stronger design. AlienSky v2 will be the definitive atmospheric scattering implementation for Babylon.js—pushing WebGPU to its absolute limits with WGSL compute shaders, while providing a safe, performant GLSL fallback. 

By defining clear data boundaries and an extensible API, we have paved the way for future modules (like volumetric clouds or weather systems) to be developed independently and integrated seamlessly. Development will proceed immediately based on this v2 specification.
